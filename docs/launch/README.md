# Atlas v0.1.0 launch kit

Public positioning: **Every coding-agent session. One terminal hub.**

This kit is for the maintainer's launch. It prepares copy and operating
instructions; it does not imply that any post, issue, or repository setting
has already been published. Use the post copy only after the public release
and download links work.

| File | Use |
| --- | --- |
| [Positioning](positioning.md) | Audience, claims, boundaries, proof |
| [Recording](recording.md) | Exact 22-second live demo plan and commands |
| [Post copy](posts.md) | Show HN, X, LinkedIn, Reddit, Discord, replies |
| [Seven-day calendar](calendar.md) | Channel-specific actions, CTAs, metrics |
| [Seed issues](seed-issues.md) | Two scoped, ready-to-paste contribution drafts |
| [GitHub setup](github.md) | Exact metadata, topics, release checks, social preview |

Before posting: verify both Linux archives and checksums, smoke-test the
documented install on a clean supported machine, enable Discussions and
private vulnerability reporting, and upload the social preview. Check that
the community reporting links work when signed in as a non-maintainer.
Publication and settings changes are separate maintainer actions.

The [README demo](../atlas-demo.gif) is an illustrative reconstruction, not a
live capture. Keep that disclosure when sharing it. The
[live-recording plan](recording.md) is a separate way to record real behavior.

Re-check each community's current promotion rules immediately before posting,
including any pinned thread requirements or moderator instructions. Skip a
channel when promotion is unwelcome. Never request coordinated upvotes,
comments, or star campaigns. Ask people to try a session, report friction,
or contribute a reproducible issue. Stay available to answer the discussion
you start. The [Show HN guidelines](https://news.ycombinator.com/showhn.html)
require something people can try and discourage soliciting votes or comments.
